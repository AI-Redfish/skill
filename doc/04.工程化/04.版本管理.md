# 版本管理

> 来源：[Skills 版本管理](https://www.runoob.com/skills/skills-versioning.html)

## 一、语义化版本号（Semantic Versioning）

格式：`MAJOR.MINOR.PATCH`

| 版本号段 | 何时递增 | 示例 |
|---|---|---|
| MAJOR | 不兼容的重大改动（如输入格式改变） | 1.0.0 → 2.0.0 |
| MINOR | 新增功能，向下兼容 | 1.0.0 → 1.1.0 |
| PATCH | Bug 修复，不影响功能 | 1.0.0 → 1.0.1 |

在 SKILL.md frontmatter 中声明：`version: 1.2.0`

## 二、用 Git 管理版本

```bash
cd my-skill/ && git init
git add . && git commit -m "feat: 初始版本 v1.0.0"

# 修改后提交
git commit -m "fix: 修复文件路径处理的空格问题"

# 打标签
git tag v1.0.1
git tag v1.1.0 -m "新增多文件批量处理功能"
```

### 推荐提交信息格式

| 前缀 | 含义 | 示例 |
|---|---|---|
| feat: | 新功能 | feat: 新增 Excel 输出支持 |
| fix: | Bug 修复 | fix: 修复空文件时的崩溃问题 |
| docs: | 文档更新 | docs: 补充参数说明 |
| refactor: | 重构（无功能变化） | refactor: 将清洗逻辑抽取为独立函数 |
| perf: | 性能优化 | perf: 大文件处理速度提升 3 倍 |

## 三、维护 CHANGELOG

在 SKILL.md 末尾附变更记录：

```markdown
## 版本历史
### v1.2.0（2026-05-18）
- 新增：支持 .xlsx 输入格式
- 优化：大文件处理速度提升 40%
### v1.1.0（2026-04-10）
- 新增：--col 参数
- 修复：列名包含空格时的解析错误
```

## 四、版本迁移（不兼容变更）

不兼容变更（修改输入格式、删除功能）需给用户明确迁移指引：

```markdown
## 迁移指南：从 v1.x 升级到 v2.0
### 主要变化：输出文件命名由 output.xlsx 改为 output_YYYYMMDD.xlsx
### 受影响场景：依赖固定输出文件名的工作流
### 迁移步骤：
1. 更新 Skill 到 v2.0
2. 检查依赖固定文件名的脚本
3. 添加 --output output.xlsx 参数保持旧行为
```

> 使用者众多时，保留旧参数并标记"已废弃"，给过渡时间，而不是直接删除。

## 五、回退到历史版本

```bash
git log --oneline            # 查看提交历史
git tag                      # 查看版本标签
git checkout v1.1.0          # 回退到指定标签
git checkout a3f7b2c         # 回退到指定提交
git checkout -b hotfix/v1.1.1 v1.1.0   # 以回退版本为基础继续开发
```

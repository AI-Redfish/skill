# 监控与可观测性

> 来源：[Skills 监控与可观测性](https://www.runoob.com/skills/skills-monitoring.html)

## 一、可观测性的三个维度

| 维度 | 回答的问题 | 实现方式 |
|---|---|---|
| 日志 Logs | 发生了什么？出了什么错？ | 结构化 JSON 日志文件 |
| 指标 Metrics | 执行了多少次？成功率？ | 追加写入指标文件 |
| 执行记录 Trace | 经过哪些步骤？每步耗时？ | 步骤级时间戳记录 |

## 二、结构化日志

每条日志是 JSON（ts / level / event / skill / 上下文），同时输出到 stderr（实时可见）和日志文件（持久化）：

```python
def log(level, event, skill="", **context):
    entry = {"ts": datetime.now(timezone.utc).isoformat(),
             "level": level, "event": event, "skill": skill, **context}
    line = json.dumps(entry, ensure_ascii=False)
    print(line, file=sys.stderr)
    with open(LOG_FILE, "a", encoding="utf-8") as f:
        f.write(line + "\n")

# 标准事件：skill_start / step_complete / skill_complete / step_failed
log("info", "skill_start", skill="data-analyzer", file="...")
log("error", "step_failed", skill="data-analyzer", step="generate_chart", error="openpyxl not found")
```

## 三、指标聚合

从日志文件统计运行状况：

```python
report = {
    "total_runs": ...,      # skill_start 次数
    "total_errors": ...,    # error 条数
    "success_rate": ...,    # (runs - errors) / runs
    "avg_elapsed_ms": ...,  # 平均耗时
    "recent_errors": errors[-5:]   # 最近 5 条错误
}
```

## 四、执行追踪（Trace）

记录每次执行各步骤耗时，快速定位慢在哪一步：

```python
class ExecutionTracer:
    def step(self, step_name): ...    # 标记步骤开始，自动记录上一步耗时
    def finish(self): ...             # 输出 {skill, total_ms, steps: [{name, elapsed_ms}]}

# 输出示例：
# {"total_ms": 1203, "steps": [
#   {"name": "读取文件", "elapsed_ms": 312},
#   {"name": "数据清洗", "elapsed_ms": 108},
#   {"name": "生成报告", "elapsed_ms": 783}]}
```

> 可观测性不是只有大规模系统才需要。个人 Skill 出问题时，一份清晰的日志文件能把排查时间从几小时缩短到几分钟。

# 设计模式与最佳实践

> 来源：[Skills 设计模式](https://www.runoob.com/skills/skills-patterns.html)

## 七种常用设计模式

### 模式一：单一职责 Skill

每个 Skill 只做一件事，做好一件事。功能越聚焦，description 越精准，触发准确率越高，维护越容易。

| 做法 | 示例 |
|---|---|
| ✅ 职责单一 | pdf-to-text（只负责提取文字） |
| ❌ 职责混杂 | pdf-tools（读取、转换、合并、加水印全放一起） |

> 信号：如果 description 需要写很长才能说清"不做什么"，说明它承担了太多职责，应该拆分。

### 模式二：防御性输入检查

脚本入口处**集中完成所有输入验证**，通过后再进业务逻辑。收集所有错误一次返回（而不是遇到第一个就崩）：

```python
def validate(args) -> list:   # 返回错误列表，空列表表示通过
    errors = []
    if not args.file: errors.append("缺少参数 --file")
    elif not os.path.exists(args.file): errors.append(f"文件不存在")
    ...
```

### 模式三：渐进式输出

耗时超过 5 秒的 Skill 应分阶段汇报进度，而不是让用户面对沉默等待：

```
> 已读取文件：runoob_data.csv（1,024 行，8 列）正在进行数据清洗...
> 数据清洗完成：删除重复行 3 条，空值填充 12 处。正在生成报告...
> 报告已生成，包含统计摘要和数据质量评估。
```

### 模式四：幂等操作

同样的输入，无论执行多少次，输出一致。非幂等操作（如每次追加内容）会导致用户重试时混乱。输出文件固定命名（覆盖）而非每次追加/新建。

### 模式五：明确的结束信号

执行完毕给出明确"完成信号"：

```
成功：> 任务完成：报告已生成，共处理 1,024 行数据，耗时约 3 秒。
失败：> 任务中断：在"数据清洗"步骤遇到错误（原因：编码不是 UTF-8）。
      建议：将文件另存为 UTF-8 格式后重新上传。
```

### 模式六：版本兼容性声明

frontmatter 中声明兼容的模型版本、Python 版本、平台，防止环境不匹配时行为异常：

```yaml
compatibility:
  claude_models: [claude-sonnet-4-20250514, claude-opus-4]
  python: ">=3.8"
  platforms: [linux]
```

### 模式七：Fail Fast（快速失败）

发现无法继续的错误立即停止并清晰报告，不带病执行：

```python
def assert_condition(condition, message, hint=""):
    if not condition:
        print(json.dumps({"status": "error", "message": message, "hint": hint}))
        sys.exit(1)

# 脚本开头集中做所有前置检查
```

## 模式速查表

| 模式 | 核心原则 | 解决的问题 |
|---|---|---|
| 单一职责 | 一个 Skill 只做一件事 | 触发不准确、难以维护 |
| 防御性输入检查 | 入口处集中验证 | 运行到一半才报错 |
| 渐进式输出 | 分阶段汇报进度 | 用户不知道是否在执行 |
| 幂等操作 | 同输入同输出 | 重试产生混乱结果 |
| 明确结束信号 | 完成后给出终态通知 | 用户不知道任务是否完成 |
| 版本兼容声明 | 声明支持的运行环境 | 环境不匹配时行为异常 |
| Fail Fast | 遇到错误立即停止 | 带着错误继续产生无效输出 |

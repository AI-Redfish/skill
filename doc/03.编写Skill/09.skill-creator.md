# SkillCreator是什么

skill-creator 不是普通 Skill，而是**创建 Skill 的 Skill**（Meta Skill / 元技能）。

作用不是完成用户任务，而是帮开发者**设计、生成、测试、优化、发布**新的 Skills。

# 安装

```bash
npx skills add https://github.com/anthropics/skills --skill skill-creator
# 或
claude install anthropics/skills/skill-creator
```

安装后本地包含：

```
skills/skill-creator/
├── SKILL.md          ← 核心说明文件
├── agents/           ← 内置的评审助手
├── eval-viewer/      ← 测试结果可视化工具
├── references/       ← 参考文档
└── scripts/          ← 自动化脚本（打包、测评等）
```

# 使用步骤

典型工作流：**需求描述 → 初始化骨架 → 编写内容 → 评审 → 打包校验 → 测试 → 发布**。

**步骤总览**

| 步骤 | 做什么 | 工具/手段 |
|---|---|---|
| 1. 描述需求 | 说清 Skill 的目标、输入输出、触发场景 | 对话 |
| 2. 初始化骨架 | 生成标准目录结构 | `scripts/init_skill.py` |
| 3. 编写内容 | 起草 SKILL.md，按需补充 scripts/、references/ | 对话 + 脚本 |
| 4. 评审优化 | 对设计、实现分别评审，按意见迭代 | `agents/` 评审助手 |
| 5. 打包 | 生成可上传的 zip | `scripts/package_skill.py` |
| 6. 校验 | 检查体积、文件类型是否合规 | `scripts/check_artifacts.py` |
| 7. 测试 | 验证触发与输出正确性 | 对话实测 / eval |
| 8. 发布 | 上传 claude.ai 或提交仓库 | Settings → Capabilities → Skills |

**案例：创建「Markdown 表格转 CSV」Skill**

完整对话过程：

```text
用户：帮我创建一个 Skill：提取 Markdown 文档中的表格并转换为 CSV 文件，
      一张表一个文件，表格较多时自动编号。

Claude：先用 init_skill.py 生成骨架：
        $ python skills/skill-creator/scripts/init_skill.py markdown-table-to-csv
        已创建 markdown-table-to-csv/{SKILL.md, scripts/, references/, assets/}

Claude：起草 SKILL.md（遵循渐进式披露：主文件只写流程，细节放 references/）：
        ---
        name: markdown-table-to-csv
        description: Extract tables from Markdown documents and convert them
          to CSV files. Use when the user wants to convert/export Markdown
          tables to CSV, or batch-process tables in docs.
        ---
        # 工作流程
        1. 读取用户指定的 Markdown 文件
        2. 调用 scripts/extract_tables.py 提取全部表格
        3. 单元格内的逗号/引号/换行按 CSV 规范转义
        4. 输出 table-1.csv、table-2.csv ……

Claude：核心解析逻辑较长，写入 scripts/extract_tables.py；
        转义规则等细节放 references/csv-rules.md。

Claude：调用评审助手检查：
        · 设计评审：description 触发词不足 → 补充 "导出表格"、"表格转CSV"
        · 实现评审：未处理单元格内竖线分隔符 → 已修复

Claude：打包并校验：
        $ python skills/skill-creator/scripts/package_skill.py \
              --skill-path skills/markdown-table-to-csv
        $ python skills/skill-creator/scripts/check_artifacts.py \
              --artifact skills/markdown-table-to-csv.zip
        校验通过：体积 < 500KB、文件类型合规、无可执行权限文件。

用户：把 notes.md 里的两个表格转成 CSV。
Claude：（自动触发 markdown-table-to-csv，生成 table-1.csv、table-2.csv）
        验证成功，Skill 可以发布。
```



# 脚本清单

## scripts/init_skill.py

 初始化骨架。

作用：生成符合规范的新 Skill 目录。

```bash
python skills/skill-creator/scripts/init_skill.py <skill_name>
# 可选：指定输出目录
python skills/skill-creator/scripts/init_skill.py my-skill --output-dir ./skills
```

案例：执行 `init_skill.py pdf-merger` 后生成：

```
pdf-merger/
├── SKILL.md      # 含 frontmatter 模板，待填写
├── scripts/      # 可执行脚本
├── references/   # 参考文档
└── assets/       # 附属资源（模板、示例文件）
```



## scripts/package_skill.py

打包。

作用：把 Skill 目录压缩为单个 zip，供上传到 claude.ai 或分发。

```bash
python skills/skill-creator/scripts/package_skill.py --skill-path skills/my-skill
# 产物：skills/my-skill.zip
```

案例：打包上面案例中的 Skill 后，在 claude.ai → Settings → Capabilities → Skills → Upload skill 直接上传 zip 即可。

## scripts/check_artifacts.py

产物校验。

作用：检查打包产物是否满足上传限制（zip 体积上限、文件类型白名单、单文件大小、可执行权限等）。

```bash
python skills/skill-creator/scripts/check_artifacts.py --artifact skills/my-skill.zip
```

案例（发现问题的输出示例）：

```text
ERROR: file 'data/model.bin' exceeds size limit (5MB)
ERROR: executable file 'scripts/run.sh' has execute permissions
建议：模型等大文件改为运行时下载；脚本去掉可执行位。
```



## eval-viewer/generate_review.py

测试报告可视化。

把 eval 测试结果汇总为 HTML 报告，便于人工审阅通过/失败情况。

```bash
python skills/skill-creator/eval-viewer/generate_review.py \
  --results evals/results/ --output evals/review.html
```

案例：跑完触发测试（判断哪些对话该/不该触发 Skill）后，用浏览器打开 review.html，逐条查看每轮对话的触发结果与模型输出。与单元测试结合参见 [04.工程化/05.单元测试.md](../04.工程化/05.单元测试.md)。

## agents

评审助手（非脚本）。

agents/ 下内置设计评审、实现评审两类子代理，由 skill-creator 在开发过程中自动调用，也可主动要求 "用 skill-creator 的评审助手重新检查这个 Skill"：

| 评审助手 | 关注点 | 常见意见 |
|---|---|---|
| 设计评审 | description 触发词、结构划分、渐进式披露 | 触发词缺失、SKILL.md 过长 |
| 实现评审 | 脚本正确性、边界处理、容错 | 未转义特殊字符、未处理空输入 |

> 注：各脚本的具体参数以安装版本的 `--help` 输出为准，不同版本略有差异。

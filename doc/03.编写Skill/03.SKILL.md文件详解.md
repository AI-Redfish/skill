# SKILL.md 文件详解

> 来源：[SKILL.md 文件](https://www.runoob.com/skills/skill-md-file.html)

## 一、基本结构

一个 SKILL.md 包含两部分：**YAML Frontmatter（元数据区域）** + **Markdown 内容（指令区域）**。

```markdown
---
name: my-skill
description: 技能描述，告诉我们什么时候使用这个技能
license: Apache-2.0
compatibility: 需要 Python 3.10+
metadata:
  author: your-name
  version: "1.0"
---

# 技能名称
这里是技能的详细指令...

## 第一步
具体的操作步骤...
```

## 二、元数据字段速查

| 字段 | 必需 | 约束 |
|---|---|---|
| name | 是 | 最多 64 字符，只能小写字母和连字符 |
| description | 是 | 最多 1024 字符，描述功能和使用场景 |
| license | 否 | 许可证名称或 bundled 许可证文件引用 |
| compatibility | 否 | 最多 500 字符，环境要求（产品、系统包、网络） |
| metadata | 否 | 任意键值对，存储额外元数据 |
| allowed-tools | 否 | 空格分隔的预批准工具列表（实验性） |

## 三、name 字段规则

- 长度 1-64 字符，只能 Unicode 小写字母（a-z）、数字和连字符（-）
- 不能以连字符开头/结尾，不能包含连续连字符（`--`）
- **必须与父目录名称一致**

```
有效：  pdf-processing / data-analysis / code-review
无效：  PDF-Processing（大写）、-pdf（连字符开头）、pdf--processing（连续连字符）
```

## 四、description 字段

在对话开始时被加载，必须包含足够关键词以便代理识别何时激活。

```
好：description: 从 PDF 文件中提取文本和表格，填写 PDF 表单，合并多个 PDF。处理 PDF 文档或用户提及 PDF、表单或文档提取时使用。
差：description: 帮助处理 PDF 文件。   # 太笼统，无法判断何时使用
```

## 五、可选字段示例

```yaml
# license
license: Apache-2.0
license: Proprietary. LICENSE.txt has complete terms

# compatibility：只在确有环境要求时添加
compatibility: Designed for Claude Code
compatibility: Requires git, docker, jq, and access to the internet
compatibility: Requires Python 3.14+ and uv

# metadata：建议使用相对独特的键名避免冲突
metadata:
  author: example-org
  version: "1.0"
  tags: [pdf, document, extraction]

# allowed-tools（实验性）
allowed-tools: Bash(git:*) Bash(jq:*) Read
```

## 六、指令区域（Markdown Body）

元数据之后的内容没有格式限制，建议包含：

- 分步操作说明
- 输入输出示例
- 常见边界情况处理

```markdown
# 技能名称
## 功能说明 —— 简要描述做什么
## 操作步骤 —— 1. 第一步 2. 第二步 3. 第三步
## 示例 —— 输入示例 / 输出示例
## 注意事项 —— 注意点列表
```

> ⚠️ 技能被激活后整个 SKILL.md 会加载进上下文。建议：**主要指令保持在 500 行以内、5000 tokens 以下**，详细参考资料移到单独文件（references/ 等）。

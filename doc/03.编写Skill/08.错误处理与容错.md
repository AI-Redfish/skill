# 错误处理与容错

> 来源：[Skills 错误处理与容错](https://www.runoob.com/skills/skills-error-handling.html)

## 一、错误处理的三个层次

| 层次 | 发生位置 | 处理方式 |
|---|---|---|
| 输入验证错误 | 执行前 | 检查输入，不合法直接拒绝并说明原因 |
| 运行时错误 | 脚本执行中 | 捕获异常，输出结构化错误信息 |
| 结果异常 | 执行完成后 | 验证输出是否符合预期，不符合触发补救 |

## 二、在 SKILL.md 中定义错误处理策略

SKILL.md 应包含明确的错误处理章节：

```markdown
## 错误处理
### 输入问题
- 文件不存在：告知路径有误，请重新上传
- 格式不支持：列出支持的格式（pdf、docx、txt）
- 文件为空：告知无法处理

### 执行问题
- 脚本运行失败：展示完整错误信息，不要隐藏
- 依赖未安装：先尝试自动安装，失败则告知手动安装
- 超时：超过 60 秒未完成，输出进度并询问是否继续等待

### 结果问题
- 输出文件为空：重新检查逻辑，说明可能原因
- 输出格式不符：展示实际输出，询问用户是否满意
```

## 三、脚本标准错误处理模式

自定义异常体系 + 统一 JSON 输出：

```python
class SkillError(Exception):
    def __init__(self, message, code):
        self.message = message
        self.code = code      # 错误码，便于程序判断错误类型

class InputError(SkillError): pass    # 输入验证错误
class ProcessError(SkillError): pass  # 处理过程错误
```

返回结构（含 hint 字段引导修正）：

```json
{
  "status": "input_error",
  "code": "FILE_NOT_FOUND",
  "message": "文件不存在：/mnt/user-data/uploads/missing.txt",
  "hint": "请检查文件路径是否正确，文件是否存在且非空"
}
```

错误分支分类处理：
- `InputError` → 用户可修正后重试
- `UnicodeDecodeError` → 给出具体修复建议（"另存为 UTF-8 后重试"）
- 未预期异常 → 完整记录便于调试

## 四、依赖自动安装

```python
def ensure_package(package_name, import_name=None):
    try:
        __import__(import_name or package_name)
        return True  # 已安装
    except ImportError:
        result = subprocess.run(
            [sys.executable, "-m", "pip", "install", package_name,
             "--break-system-packages", "--quiet"],
            capture_output=True, text=True)
        return result.returncode == 0
```

> 自动安装只适用于开发和轻量场景。生产环境应将依赖写入文档，由用户预先安装。

## 五、错误信息书写规范

好的错误信息三要素：**描述问题 + 说明原因 + 提供行动**。

| 维度 | 差的写法 | 好的写法 |
|---|---|---|
| 描述问题 | "出错了" | "文件 report.csv 不存在于上传目录" |
| 说明原因 | （无） | "可能是文件名拼写有误，或文件尚未上传" |
| 提供行动 | （无） | "请重新上传文件，或检查文件名是否正确" |

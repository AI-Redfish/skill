# 脚本扩展（scripts/）

> 来源：[Skills 脚本扩展](https://www.runoob.com/skills/skills-scripts.html)

## 一、为什么使用脚本

- 封装复杂逻辑，避免在 SKILL.md 中写大量代码
- 提供经过测试的可靠实现，让代理重复使用相同工具
- 处理更复杂的输入输出操作

> 信号：当多次执行中发现代理**重复实现相同逻辑**时，就是创建脚本的时机。

## 二、脚本编写规范

### 1. 自包含性
脚本头注释声明依赖与运行方式：
```python
#!/usr/bin/env python3
"""
PDF 文本提取脚本
依赖：pip install pdfplumber
运行：python scripts/extract_pdf.py input.pdf
"""
```

### 2. 清晰的错误处理
错误信息输出到 stderr，说明期望与实际：
```python
if len(sys.argv) < 2:
    print("错误：缺少必需的参数", file=sys.stderr)
    print("用法: python script.py <输入文件>", file=sys.stderr)
    sys.exit(1)
```

### 3. 处理边界情况
优雅处理而非崩溃：空输入、超长输入等都返回明确的验证失败信息。

## 三、在 SKILL.md 中引用脚本

使用**相对于 Skill 根目录的路径**（Agent 会自动解析，无需绝对路径）：

```markdown
## 可用脚本
- `scripts/validate.sh` — 验证配置文件
- `scripts/process.py` — 处理输入数据

## 操作流程
1. 运行验证脚本：
   bash scripts/validate.sh "$INPUT_FILE"
2. 处理数据：
   python3 scripts/process.py --input results.json
```

## 四、两种使用方式

| 方式 | 适用场景 | 需要 scripts/ 目录 |
|---|---|---|
| 一次性命令 | 只需调用现有工具 | 不需要 |
| 自包含脚本 | 需要复用的复杂逻辑 | 需要 |

### 一次性命令（各生态运行方式）

```bash
# uvx（Python）—— 隔离环境运行，缓存积极
uvx ruff@0.8.0 check .
uvx black@24.10.0 .

# pipx（Python）
pipx run 'black==24.10.0' .

# npx（Node.js）
npx eslint@9 --fix .
npx create-vite@6 my-app

# go run（Go）
go run golang.org/x/tools/cmd/goimports@v0.28.0 .
```

建议：**固定版本号**确保行为一致；在 SKILL.md 中声明前置条件（如"需要 Node.js 18+"）；命令变复杂时提取到 scripts/。

### 自包含脚本（多语言方案）

**Python PEP 723**（`# ///` 标记声明依赖，uv/pipx 直接运行）：
```python
# /// script
# dependencies = ["beautifulsoup4"]
# ///
from bs4 import BeautifulSoup
...
```
```bash
uv run scripts/extract.py
```

**Deno**：`import * as cheerio from "npm:cheerio@1.0.0";` → `deno run scripts/extract.ts`

**Bun**：无 node_modules 时自动安装缺失包 → `bun run scripts/extract.ts`

**Ruby**：`require 'bundler/inline'` + `gemfile do ... end` 内联声明 gem

## 五、为 Agent 设计脚本的要点

Agent 通过读 stdout / stderr 决定下一步，脚本设计要点：

| 要点 | 说明 |
|---|---|
| **避免交互式提示（硬性要求）** | Agent 在非交互 Shell 运行，无法响应 TTY 提示；输入一律通过参数/环境变量/stdin |
| **提供 --help 文档** | Agent 了解脚本接口的主要方式 |
| **编写有用的错误信息** | `"Error: --format must be one of: json, csv, table. Received: xml"` 而非 `"invalid input"` |
| **结构化输出** | 优先 JSON/CSV/TSV；数据输出到 stdout，进度/诊断信息输出到 stderr |
| **幂等性** | "不存在则创建"比"重复时报错"更安全 |
| **输入约束** | 用清晰错误拒绝模糊输入，而非猜测意图 |
| **Dry-run 支持** | 破坏性操作提供 `--dry-run` 预览 |
| **有意义的退出码** | 不同失败类型使用不同退出码 |
| **可预测的输出大小** | 默认输出摘要，提供 `--offset` 等参数按需获取 |
| **安全默认值** | 破坏性操作要求 `--confirm` / `--force` |

错误示例对比：
```bash
# 错误：会卡住等待输入
$ python scripts/deploy.py
Target environment: _

# 正确：清晰错误信息和引导
$ python scripts/deploy.py
Error: --env is required. Options: development, staging, production.
```

## 六、依赖分发

1. 在 SKILL.md 中说明依赖（最简单）
2. 使用虚拟环境（复杂项目）
3. 使用 Docker（需要完整运行环境）

> 确保脚本能在目标环境中运行；编写前先了解目标用户的运行环境。

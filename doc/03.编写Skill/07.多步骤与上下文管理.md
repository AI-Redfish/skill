# 多步骤流程与上下文管理

> 来源：[Skills 多步骤](https://www.runoob.com/skills/skills-multi-step.html) / [Skills 上下文](https://www.runoob.com/skills/skills-context.html)

## 一、多步骤流程设计

没有明确步骤指导时，Claude 可能跳过环节或以不一致顺序执行。显式步骤的好处：**行为可预测、用户知道在发生什么、出错易定位**。

### 步骤设计原则

| 原则 | 说明 |
|---|---|
| 每步只做一件事 | 避免一个步骤做多个不相关操作 |
| 步骤间有明确输入输出 | 上一步输出是下一步输入，不依赖隐式状态 |
| 每步执行后给出反馈 | 告知完成了什么、下一步是什么 |
| 允许中途中断 | 用户可在任意步骤暂停或修改参数 |

### SKILL.md 多步骤模板

```markdown
## 执行流程
### 第一步：读取并验证数据
1. 检查文件是否存在、格式是否支持
2. 输出基本信息（行数、列数、类型、空值统计）
3. 发现严重问题立即停止并告知用户

### 第二步：数据清洗
运行 scripts/clean_data.py，删除重复行、填充空值、去除空格
输出清洗报告（删除多少行、修改多少值）

### 第三步：生成统计摘要
运行 scripts/calc_stats.py，输出到 stats.json

### 第四步：生成报告
运行 scripts/gen_excel.py，保存到输出目录，展示下载链接

### 错误处理
任意步骤失败：展示完整错误信息 + 可能原因 + 询问跳过或重试
```

### 脚本组织方式

- **方案一（推荐复杂流程）**：每步一个脚本 `clean_data.py` / `calc_stats.py` / `gen_excel.py`
- **方案二（简单流程）**：单一主脚本，通过 `--step clean|stats|excel` 参数控制

### 步骤间依赖检查

后续步骤依赖前面输出文件时，执行前先检查依赖是否存在：

```python
missing = [f for f in required_files if not os.path.exists(f)]
if missing:
    print(f"错误：{step_name} 缺少前置文件：{missing}")
    print("请先完成前置步骤。")
```

> 明确的依赖检查能在错误发生时立刻定位缺失环节，而不是在最后一步才暴露问题。

## 二、上下文与状态管理

Claude 的每次 API 调用都是**无状态**的，但一次连续对话中所有历史消息都在上下文窗口里。

### 状态存储位置

| 状态类型 | 存储位置 | 有效范围 |
|---|---|---|
| 对话历史 | 上下文窗口 | 当前会话 |
| 中间文件 | 工作目录 | 当前会话 |
| 输出文件 | /mnt/user-data/outputs/ | 持久化，用户可下载 |
| 已安装的 Skill | skills 目录 | 跨会话持久化 |

Skills 本身不具备数据库能力；跨会话数据需用户保存或写入持久化输出目录。

### 多轮对话状态管理

在 SKILL.md 中明确定义阶段流转：

```markdown
### 阶段一：信息收集 —— 询问文件路径、分析目标；未收集齐不执行
### 阶段二：确认执行 —— 展示执行计划，等待用户确认
### 阶段三：执行并输出 —— 实时告知进度
用户说"重新开始" → 清除已收集信息，回到阶段一
```

复杂任务可用 JSON 文件保存中间状态（save_state / load_state / clear_state）。

### 防止上下文污染

同一对话中多次触发 Skill 时，旧参数可能污染新执行。规定参数优先级：

1. **用户最新消息中明确指定的参数**（最高）
2. 本次请求中上传的文件
3. 对话历史中提到的参数（仅在当前消息未指定时使用）
4. Skill 定义的默认值（兜底）

有疑问时先确认："我将使用 runoob_v2.csv（您刚上传的），而非之前的 runoob_v1.csv，是否正确？"

### 上下文长度优化

| 策略 | 做法 | 效果 |
|---|---|---|
| 避免重复输出大块内容 | 引用之前输出的文件路径 | 减少上下文占用 |
| 用文件传递中间数据 | 大数据集写文件，对话只传路径 | 避免大数据占满窗口 |
| 及时告知阶段完成 | 每阶段结束明确说"第一步完成" | 用户知道进度，减少追问 |

> 上下文窗口是有限资源。传的数据越多，留给推理和生成的空间越少。**大文件始终通过路径而非内容传递**。

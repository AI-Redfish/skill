# 描述编写与触发优化

> 来源：[Skills 描述](https://www.runoob.com/skills/skills-description.html) / [Skills 描述优化技巧](https://www.runoob.com/skills/skills-description-optimize.html)

## 一、为什么 description 最重要

- 发现阶段代理只加载 name 和 description，它是判断是否激活技能的**主要/唯一依据**
- 描述不好会导致：误报（不该激活时激活）、漏报（该激活时没激活）、激活错误技能

## 二、描述的基本结构

好描述 = **功能说明 + 触发条件**：

```
description: 从 PDF 文件中提取文本和表格，填写 PDF 表单，合并多个 PDF。处理 PDF 文档或用户提及 PDF、表单或文档提取时使用。
#             ↑ 功能说明                                ↑ 触发条件
```

### 四要素结构

| 要素 | 作用 | 示例 |
|---|---|---|
| 核心功能一句话 | 最直接说明 Skill 是什么 | "处理 Excel 和 CSV 格式的表格数据" |
| 具体能力列举 | 列出 3-5 个典型操作 | "包括数据清洗、统计分析、图表生成" |
| 触发场景描述 | 什么时候应该用 | "当用户提到数据分析、报表、统计时触发" |
| 推动性语句（可选） | 解决"低触发率"问题 | "即使用户没提到格式，只要涉及表格数据就应使用" |

## 三、编写技巧

1. **包含具体触发关键词**：把用户可能使用的词汇写进描述
2. **具体而非笼统**："处理各种文件" ❌ → "处理图像文件，包括调整大小、转换格式、应用滤镜" ✅
3. **说明多个使用场景**：帮助更准确匹配
4. **区分相似技能**：多个相关技能的描述要有明显区别（如 pdf-extract vs pdf-form）

## 四、长度控制

理想长度 **50-150 字**，不是越长越好：

| 情况 | 建议长度 |
|---|---|
| 简单技能 | 50-100 字符 |
| 中等复杂度 | 100-200 字符 |
| 复杂技能 | 200-400 字符 |

## 五、常见问题与修正

| 问题 | 原因 | 修正方向 |
|---|---|---|
| 技能总是被激活 | 描述过于宽泛 | 添加限定条件和使用场景 |
| 技能从未被激活 | 缺少用户可能用的关键词 | 添加更多触发词 |
| 激活了错误技能 | 多个技能描述相似 | 增加描述区分度 |
| 使用内部实现术语 | 如"调用 pandas 分析" | 改为用户视角的业务描述 |

迭代优化示例：

```
v1（可能漏报）：提取 PDF 文本。
v2（减少漏报）：从 PDF 文件中提取文本内容和表格数据。使用场景：提取 PDF 文字、读取 PDF 内容、PDF 转文本。
v3（最终）：…用户提及「PDF 提取」「读取 PDF」「PDF 文字」「PDF 内容」等关键词时使用。
```

## 六、自动化优化（skill-creator）

### 第一步：准备测试用例（evals/trigger-eval.json）

```json
[
  {"id": "should_trigger_01", "prompt": "帮我分析 runoob_sales.csv，找出月度销售趋势", "expected": true},
  {"id": "should_trigger_02", "prompt": "这个 Excel 文件里哪些列有空值？帮我统计一下", "expected": true},
  {"id": "should_not_trigger_01", "prompt": "Excel 和 CSV 有什么区别？", "expected": false},
  {"id": "should_not_trigger_02", "prompt": "帮我写一封邮件", "expected": false}
]
```

### 第二步：运行优化循环

```bash
python -m scripts.run_loop \
  --eval-set evals/trigger-eval.json \
  --skill-path data-analyzer/ \
  --model claude-sonnet-4-20250514 \
  --max-iterations 5 --verbose
```

脚本自动：评估 → 修改 description → 再评估，循环迭代，输出最优结果（best_description）。

### 第三步：应用结果并重新打包

```bash
python -m scripts.package_skill data-analyzer/
```

### A/B 对比测试

对两个版本的 description 分别 run_eval，用 eval-viewer 生成对比报告。

> ⚠️ 评估以**测试集**得分为准。训练集高分但测试集低分 = description 过拟合了测试用例。

## 七、测试要点

1. **基本功能测试**：用描述中的关键词测试能否激活
2. **边界情况测试**：测试可能触发但不应该触发的场景
3. **迭代优化**：误报增多→加限定条件；漏报增多→加触发词；激活错误→增强区分度

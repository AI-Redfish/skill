# Skill 目录结构详解

> 来源：[Skills 目录结构](https://www.runoob.com/skills/skills-dir.html)

## 一、Skill 与 Agent 的关系

Skill 是独立的能力单元；Skill 本身不决定什么时候用，**决策者是 Agent**。

Agent 不会一次性加载所有 Skill 完整内容：先读每个 Skill 的 description，命中后再加载完整内容（几百个 Skills 全量加载会浪费 Token）。

## 二、标准目录结构

```
my-skill/
│
├── SKILL.md          ← 核心执行文件
├── metadata.json     ← 元信息
├── examples/         ← 示例目录
│   ├── example1.md
│   └── example2.md
├── scripts/          ← 可执行脚本
│   ├── main.py
│   └── utils.py
├── resources/        ← 资源目录
│   ├── prompt.md
│   └── config.yaml
├── tests/            ← 测试目录
│   ├── test_cases.md
│   └── eval.yaml
├── README.md         ← 使用说明
└── CHANGELOG.md      ← 变更日志
```

## 三、各文件职责

### SKILL.md（核心执行文件）

应包含：Description（功能描述，供匹配）、When to use / When NOT to use（避免误触发）、Input（输入格式）、Instructions（执行步骤）、Output（输出格式）。

规范示例（PDF 分析）：

```markdown
# PDF 分析 Skill
## Description — 用于分析 PDF 内容并生成摘要
## When to use — PDF 阅读、摘要提取、内容分析
## When NOT to use — 图片编辑、视频处理
## Input — PDF 文件
## Instructions — 1.提取文本 2.识别章节结构 3.总结内容 4.输出重点
## Output — Markdown 格式摘要
```

**常见错误写法**：只有"读取 PDF / 总结内容 / 返回结果"三行——不知道何时用/不用、输出格式不明确、易与其他 Skill 冲突。

### metadata.json（机器可读元信息）

```json
{
  "name": "pdf-analyzer",
  "version": "1.0.0",
  "description": "分析 PDF 并生成摘要",
  "tags": ["pdf", "summary"],
  "category": "document"
}
```

**description 最重要**：用户请求后，Agent 扫描所有 Skill 的 description，发现匹配后加载完整内容并执行。

### examples/（Few-shot 示例）

| 作用 | 说明 |
|---|---|
| 提供 Few-shot 示例 | 帮助模型通过示例理解期望行为 |
| 规范输出格式 | 通过示例明确输出结构和风格 |
| 提高输出稳定性 | 减少随机行为，结果更可预测 |

> 经验：好的 examples 往往比增加提示词更有效。

### scripts/（可执行脚本）

需要真正执行代码的场景：读取 PDF、OCR、数据库、数据处理、生成图表等。工作流：读取文件 → 执行脚本 → 获取结果 → 交给大模型处理。

### resources/（资源目录）

配置与代码分离：Prompt 模板、配置文件（config.yaml）、文本模板、图片、SQL 模板。修改参数不需要改代码。

### tests/（测试目录）

验证效果、回归测试、自动评估、A/B 测试。没有测试的 Skill 容易"改了一句话，旧功能突然失效"。

### README.md

面向开发者的安装使用说明。

## 四、完整调用流程

```
用户上传 PDF 并总结
  → Agent 扫描所有 Skills
  → 发现 description 匹配 → 命中 pdf-analyzer
  → 读取 SKILL.md → 调用 extract.py → 提取内容
  → 生成摘要 → 返回结果
```

## 五、为什么要目录化（而不是一个 prompt.txt）

| 单文件问题 | 目录化优势 |
|---|---|
| 无法维护（内容堆一个文件） | 可维护（职责清晰，定位快） |
| 无法测试 | 可测试（独立测试目录） |
| 无法复用 | 可复用（脚本配置跨 Skill 共享） |
| 无法版本管理 | 可扩展（新增功能只需加文件） |
| 无法多人协作 | 可发布（目录打包即可分发） |

> **总结**：Skill 本质不是提示词，而是一套完整的软件能力包。Prompt 只能解决一次问题，Skill 是把能力沉淀成资产。

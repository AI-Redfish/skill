# MySQL 到 Kingbase 兼容性说明

对每个变更的 Kingbase 迁移文件执行本清单。必须确认转换后的业务语义，不得盲目替换文本。

## 会话与标识符

| MySQL | Kingbase |
|---|---|
| `USE db;` | Flyway 已设置 `currentSchema` 时直接删除，否则使用 `SET search_path TO schema;` |
| 反引号 | 小写标识符直接去除；只有必须保留大小写时才使用双引号 |
| `db.table` | 改为 `schema.table`；本仓库的数据库目录名通常与 schema 名相同 |
| `DELIMITER`、MySQL 存储过程语法 | 改用 PL/pgSQL 函数或 `DO $$ ... $$` |

## 字段与表结构 DDL

| MySQL | Kingbase |
|---|---|
| `MODIFY COLUMN c type ...` | 使用 `ALTER COLUMN c TYPE type`，默认值和可空性分别修改 |
| `CHANGE COLUMN old new type` | 先执行 `RENAME COLUMN old TO new`，再修改类型、默认值和可空性 |
| `AFTER other`、`FIRST` | 不支持，应删除；字段物理顺序不应作为业务契约 |
| 内联 `COMMENT '...'` | 改为 `COMMENT ON TABLE/COLUMN ... IS '...';` |
| `ENGINE=InnoDB` | 删除 |
| `DEFAULT CHARSET`、`CHARACTER SET` | 删除，统一使用数据库编码 |
| MySQL `COLLATE` 名称 | 删除；只有明确验证 Kingbase 排序规则后才进行映射 |
| `AUTO_INCREMENT` | 改为标识列或序列，例如 `GENERATED BY DEFAULT AS IDENTITY` |
| `UNSIGNED` | 没有直接等价语法；根据业务扩大类型或增加 `CHECK (c >= 0)` |
| `ON UPDATE CURRENT_TIMESTAMP` | 改用触发器，或由应用和更新 SQL 显式维护 |
| `CREATE TABLE` 中使用 `KEY` 定义索引 | 拆分为独立的 `CREATE INDEX [IF NOT EXISTS]` 语句 |

## 常见类型映射

| MySQL | Kingbase |
|---|---|
| `tinyint` / `tinyint(1)` | `smallint`；只有应用值确实为布尔值时才使用 `boolean` |
| `datetime` | `timestamp` |
| `longtext`、`mediumtext` | `text` |
| `double` | `double precision` |
| `blob`、`longblob` | `bytea` |
| `json` | Kingbase 版本支持时使用 `json`/`jsonb`，否则使用 `text` |
| `enum`、`set` | 根据业务改为带 `CHECK` 的 `varchar`、字典表或数组 |

忽略 `int(11)` 等 MySQL 整数显示宽度，它们不表示数值精度约束。

## 插入与 upsert

| MySQL | Kingbase |
|---|---|
| `REPLACE INTO` | 改为 `INSERT ... ON CONFLICT (key) DO UPDATE SET ...` |
| `INSERT IGNORE` | 基于真实约束改为 `INSERT ... ON CONFLICT DO NOTHING` |
| `ON DUPLICATE KEY UPDATE` | 改为 `ON CONFLICT (key) DO UPDATE SET ...` |
| upsert 更新部分的 `VALUES(col)` | 改为 `EXCLUDED.col` |

不得猜测冲突键，必须先确认主键或唯一约束。`REPLACE` 具有先删除再插入的语义，必须确认转换成更新后业务行为仍然等价。

## 关联更新与关联删除

```sql
-- MySQL
UPDATE target t JOIN source s ON s.id = t.id SET t.value = s.value;

-- Kingbase
UPDATE schema.target t
SET value = s.value
FROM schema.source s
WHERE s.id = t.id;
```

```sql
-- MySQL
DELETE t FROM target t JOIN source s ON s.id = t.id;

-- Kingbase
DELETE FROM schema.target t
USING schema.source s
WHERE s.id = t.id;
```

## 表达式与函数

| MySQL | Kingbase/PostgreSQL 风格等价写法 |
|---|---|
| `IFNULL(a,b)` | `COALESCE(a,b)` |
| `IF(cond,a,b)` | `CASE WHEN cond THEN a ELSE b END` |
| `GROUP_CONCAT(x)` | `string_agg(x::text, ',')` |
| `DATE_FORMAT(ts, fmt)` | `to_char(ts, mapped_fmt)` |
| `STR_TO_DATE(s, fmt)` | 使用已映射格式的 `to_timestamp`/`to_date` |
| `FIND_IN_SET(v, csv)` | 经过类型确认后改为 `v = ANY(string_to_array(csv, ','))` |
| `CONCAT(a,b)` | 使用 `concat(a,b)` 或 `a || b`，并确认空值语义 |
| `LIMIT offset,count` | `LIMIT count OFFSET offset` |
| `NOW()` | `CURRENT_TIMESTAMP` 或 `now()` |

日期格式标记必须逐项映射，MySQL 与 PostgreSQL 风格的格式标记并不完全相同。

## JSON 与字符串

- 去除 MySQL JSON 双引号前的反斜杠。Kingbase SQL 字面量应写成 `'{"key":"value"}'`，双引号前不得有反斜杠。
- 字符串中的单引号使用两个单引号转义：`''`。
- 不得假设 MySQL JSON 路径函数与 Kingbase 签名相同。先确认 `json`/`jsonb` 支持情况，再显式转换操作符和函数。
- 处理 `${...}` 文本时，注意 Flyway 配置了 `placeholderReplacement=false`。

## 过程化语法与临时对象

- MySQL 的 `DECLARE`、`IF`、异常处理器、预处理语句和 `DELIMITER` 代码块不能直接在 Kingbase 中执行。
- 改用 `CREATE OR REPLACE FUNCTION ... LANGUAGE plpgsql` 或 `DO $$ ... $$`。
- 删除辅助函数时必须带上准确的参数签名，避免函数重载产生歧义。
- 迁移结束后不得遗留通用辅助函数。
- 能用 CTE 表达时，避免创建固定名称的临时表；递归展开使用 `WITH RECURSIVE`。

## 静态排除扫描

完成 Kingbase 文件转换后，以下命令应当没有输出：

```bash
rg -n '\\|`|^\s*USE\s|REPLACE\s+INTO|INSERT\s+IGNORE|ON\s+DUPLICATE\s+KEY|MODIFY\s+COLUMN|CHANGE\s+COLUMN|AUTO_INCREMENT|UNSIGNED|ENGINE=|CHARACTER SET|\bCOLLATE\b|\bAFTER\b|\bFIRST\b|DELIMITER|FIND_IN_SET|GROUP_CONCAT|IFNULL\(' <file>
```

静态检查不能证明运行时兼容。存在凭据和客户端工具时，必须在一次性 Kingbase 数据库上执行完整 Flyway 迁移。

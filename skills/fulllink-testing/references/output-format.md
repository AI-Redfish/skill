# 用例文档输出格式（output-format）

生成用例文档的固定模板。章节顺序不可调整；表格列名与
`scripts/validate_cases.py` 的解析规则一一对应，改名会导致校验失败。

## 文档骨架

```markdown
# <需求名> 测试用例

## 一、范围声明
- 依据：<PRD 路径/版本>、<技术文档路径/版本>
- 本期不实现：<R 编号/功能点列表 + 一句话原因>（无则写"无"）
- 术语与口径：<状态枚举/关键口径一句话说明>（无则省略本行）

## 二、需求解构
### 2.1 功能模块清单
| 模块码 | 模块名 | 端 | 功能点摘要 | 关联 AC |
### 2.2 AC 清单
| AC 编号 | 原文要点 | 所属功能点 |

## 三、用例总览
| 维度 | 数量 |（正例/反例/边界/权限 各一行）
| 优先级 | 数量 |（P0/P1/P2）
合计 N 条。

## 四、分模块用例
### <模块名>（TC-<模块码>）
| 用例编号 | 关联AC | 用例类型 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
|---|---|---|---|---|---|---|
| TC-XX-001 | AC7-1 | 正例 | P0 | ... | 1. ...<br>2. ... | 1. ...<br>2. ... |

## 五、AC 覆盖统计
| 指标 | 值 |
|---|---|
| AC 总数 / 已覆盖 / 覆盖率 | x / y / z% |
| 未覆盖 AC 及原因 | ACxx：<原因>（每条一行） |

## 六、缺口清单
- <设计时发现的需求模糊点/待确认项，供测试与产品确认>（无则写"无"）
```

## 列定义（validate_cases.py 解析契约）

| 列名 | 必填 | 约束 |
|---|---|---|
| 用例编号 | 是 | 唯一；格式 `TC-<模块码>-<三位序号>`（正则 `TC-[A-Za-z0-9-]+-\d{3}`） |
| 关联AC | 建议必填 | 一个或多个 AC/TD 编号，空格分隔；为空产生 warning |
| 用例类型 | 是 | 枚举：正例 / 反例 / 边界 / 权限（其他类型用"其他"） |
| 优先级 | 是 | 枚举：P0 / P1 / P2 |
| 前置条件 | 是 | 测试人员可操作的准备动作 |
| 测试步骤 | 是 | 编号步骤，`<br>` 分隔 |
| 预期结果 | 是 | 编号断言，与步骤一一对应，禁止"正常/正确"等模糊词 |
| 所属模块 | 否 | 可由所在分节推断；填写时与分节名一致 |

## 解析规则说明

- 只解析 `## 四、分模块用例` 之后、以 `| TC-` 开头的表格行；
- 多个 AC 用空格分隔（如 `AC7-1 AC7-2`）；
- 预期结果中的多断言建议与步骤编号对应（`1.` `2.`），便于执行打勾。

# 评审指南：机器检查 + AI 双评审 + 95% 置信放行

评审门（SKILL.md §4）的完整标准。目标：**反复测试和审核，直到有 95% 的把握
这个 skill 完全没问题、能满足需求**才放行进入测试门。

## 评审顺序（缺一不可）

1. **机器检查**：`review_checklist.py` 全过（error=0；warning 逐条确认"可接受"或修复）
2. **AI 设计评审**：下文清单 A
3. **AI 实现评审**：下文清单 B（可参考官方 `agents/grader.md` 的证据标准、
   `agents/analyzer.md` 的分析视角，能力表有 `agents` 时读取）
4. **置信度判定**：对照清单 C 逐条自评，≥95% 才 `gate.py review-pass`

每轮评审意见写入 `<workspace>/review-round-N.md`（结构见文末）。
评审不过 → `gate.py review-fail --issues-file <该文件>` → 修改 → **从机器检查重走**。

## 清单 A：设计评审

- [ ] **双闭环内嵌**：SKILL.md 含理解闭环/输出审查闭环章节，一次一问、十要素、
      双 95%、最终输出格式四要素完整，未被弱化、未与默认值/流程矛盾
- [ ] **单一职责**：只解决一类问题，边界清晰；name 一眼看出用途
- [ ] **触发准确**：description 同时含"做什么 + 什么时候用"；覆盖用户真实说法
      （含口语/缩写/中英变体）；与相邻 skill 无冲突
- [ ] **负向场景**：明确"不适用场景"，简单问答不会误触发
- [ ] **渐进式披露**：SKILL.md ≤500 行只留流程；细节在 references/ 且被正确引用；
      大文件（>300 行）有目录
- [ ] **输入输出契约**：必填/可选/默认值明确；缺关键信息"先问再做"；
      输出格式固定（模板/表格/JSON）
- [ ] **参数决策合理**：默认值符合直觉；影响结果的决策点是否该问用户
- [ ] **符合需求澄清记录**：逐条对照用户确认的需求，无遗漏、无擅自加戏

## 清单 B：实现评审

- [ ] **脚本正确性**：核心逻辑人工推演 + 单测覆盖（正常/边界/错误三路径）
- [ ] **边界处理**：空输入、超大输入、非法格式、编码（UTF-8/BOM）、路径含空格/中文
- [ ] **容错**：错误信息三要素（问题+原因+行动）；依赖缺失有降级；不吞异常
- [ ] **Agent 友好**：无交互输入；JSON stdout / 日志 stderr；退出码语义固定且被 SKILL.md 记载
- [ ] **幂等与安全**：重复执行同结果；破坏性操作有 `--confirm`/`--dry-run`；
      无命令注入（用户输入进 shell 前转义/白名单校验）
- [ ] **密钥卫生**：无硬编码凭据；环境信息走 `.agents/.env`；产物不写回仓库
- [ ] **uv 规范**：第三方依赖全部 PEP 723 声明；标准库优先
- [ ] **性能**：重复操作已脚本化；大文件分块/走文件路径不塞上下文；
      可缓存处有缓存（如 uv 的依赖缓存、文件指纹）

## 清单 C：95% 置信判据（全部满足才可声明 ≥95%）

1. 机器检查全过，warning 逐条有"接受理由"
2. 清单 A、B 无未解决的 P0（功能性错误/安全问题）与 P1（高概率踩坑）问题；
   P2（建议）可遗留但需记录
3. **负向验证**：至少 2 个"不应触发/不应执行"的用例推演通过
4. **错误路径演练**：至少 1 个典型失败场景（文件缺失/依赖缺失/非法输入）
   的行为符合"错误处理"章节描述
5. **边界抽查**：至少 2 个边界输入（空/极值/特殊字符）推演结果正确
6. **需求对照**：需求澄清记录逐条核对，全部满足
7. **fresh eyes 复读**：以"第一次读这个 skill 的 AI"视角通读 SKILL.md，
   无歧义步骤、无未定义引用（引用的 references 文件真实存在）

自评模板（写入 review-round-N.md 结尾）：

```
置信度自评：__%
- 判据1 机器检查: 通过（N warning 已确认）/ 未通过
- 判据2 P0/P1: 无 / 有（列清单）
- 判据3 负向验证: 通过（用例…）
- 判据4 错误路径: 通过（场景…）
- 判据5 边界抽查: 通过（输入…）
- 判据6 需求对照: 全部满足 / 缺口…
- 判据7 fresh eyes: 无歧义 / 发现…
结论：放行（≥95%）| 继续修改（原因…）
```

## review-round-N.md 结构

```markdown
# 评审记录 — 第 N 轮（<时间>）
## 机器检查
- checklist JSON: checklist-round-N.json（failed=0, warned=X）
- warning 确认: <逐条：接受原因 / 已修复>
## 设计评审（清单 A）
- 通过项摘要 / 问题清单（编号、位置、建议）
## 实现评审（清单 B）
- 通过项摘要 / 问题清单
## 置信度自评
<上文模板>
```

## 与官方评审助手的配合

AI 评审本身遵循输出审查闭环：形成评审结论→自查（证据是否真实、是否遗漏）→修正→
再审查，直到 95% 信心才写入 review-round-N.md。

能力表有 `agents` 时（官方 agents/grader.md 等）：
- 对**测试产物**的断言判定参考 grader.md 的证据标准（PASS 需真实证据，非表面合规）
- 对**基准数据**的解读参考 analyzer.md（区分"无论有无 skill 都过"的非区分性断言、
  高方差易碎用例、时间/ token 取舍）

## 修改后的重评范围

测试失败（`test-fail`）退回编写后，修改涉及的每个文件都要重走：
机器检查（全量）→ 双评审（至少覆盖改动点及其上下游）→ 置信度重评。
不允许"只改了一行就免评审"。

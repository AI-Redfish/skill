# 接口性能与批量/定时任务约束（吸收 bps-code-implementation 性能清单 + 会话实战）

## 1. 接口性能自检表

| 检查项 | 通过标准 |
| --- | --- |
| 分页 | 所有列表接口有分页和 pageSize 上限，后台管理默认不超过 50 |
| 索引 | 过滤、排序、join 字段有索引或设计解释 |
| 数据量 | Service/Mapper 注释或设计说明中能追溯预估行数和日增量 |
| 批量查询 | 列表组装不循环逐条查库（用 inList 批量查询 + 内存组装） |
| 导入导出 | 超过 1,000 条的数据导出、文件解析、批量处理异步化 |
| 事务 | 写接口有明确事务边界，重复提交和并发冲突有处理 |
| 缓存 | 缓存 key、TTL、失效策略和权限/租户隔离明确 |
| 外部调用 | 有超时、失败处理、重试边界或异步补偿 |
| 响应目标 | 常规列表 p95<=500ms，复杂统计/写接口 p95<=800ms，p99<=2000ms |

无法满足技术设计中的性能目标时，先反馈设计风险，不用隐藏复杂度的方式硬写代码。

## 2. 批量/定时任务性能防护（会话实战沉淀，必选项）

以「历史已打租赁标签资产自动同步」任务为例，以下每一项都是用户明确要求或踩坑后补充的：

| 防护项 | 实现要求 | 参考配置 |
| --- | --- | --- |
| 执行周期 | 小时级（如 12 小时）而非分钟级；除非用户明确要求更高频率 | `fixed-delay: 43200000` |
| 分批短事务 | 每批一个独立事务（如 200 资产/批），锁持有时间短，失败只回滚当前批 | `batch-size: 200` |
| 批间休眠 | 批与批之间 sleep（可配、可中断），摊平数据库连接与行锁占用 | `batch-interval-millis: 500` |
| 单轮上限 | 单租户/单轮设批次上限，超出自动停止留待下轮，输出 WARN | `max-batches-per-tenant: 1000` |
| 游标翻页 | 按 `asset_info_id` 升序 + `gt` 条件推进，禁止 OFFSET 深分页 | — |
| 扫描上限 | 逐页扫描设页数上限（如 400 页），防全量空转 | — |
| 内存有界 | 只保留当页数据与结果集，过程计数器化；内存占用与批次大小相关、与总量无关 | — |
| 配置防呆 | batch-size/interval/上限非法时直接跳过不碰库，输出 ERROR | — |
| 中断友好 | sleep 捕获 `InterruptedException` 后恢复中断标志，剩余留待下轮 | — |
| 多实例互斥 | 分布式锁（Redisson `tryLock(0, ...)` 看门狗续租）；跳过而非等待 | — |
| 租户隔离 | 按租户数据源路由（`DataSourceContextHolder` + `TokenData`），单租户失败不阻塞其他租户 | — |
| 可观测 | 每租户输出批次数/资产数/耗时；截断与跳过均有日志 | — |

## 3. 查询与翻页模式

- 候选集扫描：单表 MP 分页查询（`PageMethod.startPage` + `LambdaQueryWrapper` + `gt` 游标），逐页在内存过滤，凑满一批或扫完即止；`PageMethod.clearPage()` 放 `finally`。
- 复杂过滤（多表 EXISTS/聚合）确需 SQL 时，一个查询只做一件事；能拆成单表 MP 查询 + 内存过滤的优先拆。
- 每页处理 = 1 次扫描查询 + 少量 IN 校验查询；避免"每页再触发全量扫描"的嵌套放大。

## 4. 内存安全清单

- 过程变量只保留：当页数据、结果集（≤batchSize）、游标、计数器。
- 大集合传递用迭代/流处理，不复制整个集合。
- 返回值不携带本批不需要的大对象列表（如同步任务只返回计数）。

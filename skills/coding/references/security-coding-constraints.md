# 编码安全约束（吸收 bps-code-implementation/references/security-coding-constraints.md）

> 落代码、补缺陷、改接口时自检。目标：编码阶段消除可预见的越权、注入、敏感数据泄露、文件越权和异步链路安全问题。

## 1. 阻断条件（命中先停止实现，补设计依据或向用户反馈）

1. 新增或变更外部可访问接口，但没有权限码、登录态要求、数据范围或明确的 `@SaIgnore` 理由。
2. 接口涉及租户、院区、组织、角色、人员、空间、工单、合同等业务数据，但没有数据隔离口径。
3. 需要系统身份、管理员身份、跨租户查询、手工设置 `TokenData` 或绕过权限拦截，但没有设计依据（确需系统任务时明确调用身份与最小权限，并记录审计）。
4. 需要动态 SQL、动态表名/列名/排序、批量导入、文件下载、二维码/外链或开放回调，但没有白名单、签名、归属校验或失败处理。
5. 涉及密码、密钥、token、验证码、身份证、手机号、患者/人员信息、文件直链等敏感数据，但没有存储、返回、日志和脱敏规则。

## 2. 权限与身份

| 检查项 | 编码要求 |
| --- | --- |
| Controller 权限 | 外部可访问端点默认添加 `@SaCheckPermission("entity.action")` 或复用已有权限常量 |
| 公开接口 | `@SaIgnore` 只用于登录、回调、扫码/H5 等设计明确场景；必须有签名、一次性码、过期时间或服务端归属校验 |
| 写操作 | 新增、修改、删除、审批、导入、导出、批量操作使用独立权限，不复用只读权限 |
| 服务内部调用 | Feign、异步任务、消息消费不能默认继承前端权限；必须明确调用身份和最小权限 |
| 系统身份 | 禁止随意构造管理员 `TokenData`；系统任务记录来源、租户、业务 ID 和审计日志 |

## 3. 租户与数据范围

1. 新增业务表默认包含并维护 `tenant_id`，插入时从 `TokenData.takeFromRequest()` 或受控任务上下文设置。
2. 查询、详情、更新、删除、导出和文件下载都必须按租户及设计要求过滤院区、组织、人员、空间或角色范围。
3. 不信任客户端传入的 `tenantId`、`userId`、`deptId`、`campusId`、`roleId`、`isAdmin` 或数据范围条件。
4. 更新/删除前先查询归属或在 SQL 条件中带上租户/数据范围，避免只按主键操作。
5. 缓存 key、分布式锁 key、异步任务 key 必须包含租户及必要的数据范围维度。

## 4. 输入校验与注入防护

| 风险点 | 编码要求 |
| --- | --- |
| DTO 入参 | 校验必填、长度、枚举、时间范围、数量上限、状态迁移和业务归属 |
| SQL 参数 | 使用 `#{}`、MyBatis-Plus Wrapper 或 `<foreach>` 参数化，禁止拼接用户输入 |
| 模糊搜索 | 对用户关键字使用仓库已有转义模式：`MyCommonUtil.replaceSqlWildcard(...)` 或现有 `safeXxx` 字段 |
| 动态排序 | sort field、direction、统计维度只能来自服务端白名单 |
| 批量入参 | 限制批量 ID 数、导入行数、导出条数和文件大小；空集合、超长集合给出明确错误 |
| 反序列化 | 禁止把用户输入作为类名、表达式、脚本、模板路径或反序列化类型 |

## 5. 敏感数据与日志

1. 密码使用 `PasswordEncoder` 等现有能力处理，禁止明文存储、明文比较或自造加密算法。
2. secret、accessKey、privateKey、token、验证码、短信内容禁止提交仓库；配置使用占位符、环境变量或密文配置。
3. 日志不得输出 token、cookie、密码、验证码、完整身份证、完整手机号、文件直链、签名密钥和完整请求体。
4. VO、导出文件、操作日志和错误提示按设计脱敏；没有脱敏规则时先反馈阻断。
5. 异常响应只返回可理解的业务错误，不透出 SQL、堆栈、内部路径、对象存储 key 或第三方密钥。

## 6. 文件、导入和导出

1. 上传校验文件大小、扩展名、MIME、数量上限和业务归属；不要只信任客户端文件名。
2. 下载、预览、导出前校验文件所属租户、业务对象权限和数据范围。
3. 禁止按客户端传入的绝对路径或 `../` 片段读写文件；对象存储 key 由服务端生成或从可信记录读取。
4. 导入必须有模板版本、字段校验、失败明细、重复策略、部分成功/回滚策略和最大行数。
5. 大文件解析、批量导出、二维码打包和 PDF 生成优先异步化，并限制任务频率。

## 7. 外部调用、开放接口和异步链路

| 场景 | 编码要求 |
| --- | --- |
| 外部 HTTP/RPC | 设置超时、失败处理、重试边界和熔断/降级口径；禁止无限重试 |
| OpenAPI/回调 | 使用签名、时间戳、nonce、防重放和来源校验；签名密钥不写日志 |
| 消息消费 | 校验消息来源、租户、业务 ID、幂等键和状态机；失败可重试且不重复写脏数据 |
| 异步任务 | 显式传递最小必要上下文，记录任务发起人、租户和业务 ID |
| 二维码/短链 | 使用一次性或有过期时间的服务端 token，扫码后仍需校验业务对象归属 |

## 8. 状态、事务和并发

1. 写接口必须校验当前状态和允许的状态迁移，禁止只靠前端按钮控制。
2. 重复提交、审批、领取、撤回、批量处理使用业务锁、幂等键、唯一约束或乐观锁。
3. 事务边界放在 Service 层；外部慢调用不要包在长事务中。
4. 批量写入要定义部分失败策略，失败后不产生孤儿数据、重复消息或权限不一致。
5. 重要写操作保留操作日志或业务审计记录。

## 9. 安全测试要求（至少覆盖）

1. 无登录、无权限、错误权限、只读权限调用写接口。
2. 使用其他租户、其他院区、其他组织的数据 ID 访问详情、更新、删除、导出、下载。
3. SQL 通配符、非法排序字段、超长关键字、超大批量 ID、非法枚举、非法状态迁移。
4. 上传非法类型、超大文件、伪造扩展名、下载他人文件、导入错误模板和重复数据。
5. 外部回调签名错误、时间戳过期、nonce 重放、异步消息重复消费。

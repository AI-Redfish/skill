# 原型忠实还原分册（需求带原型图/设计稿时强制执行）

> 触发：用户提供了原型图、设计稿、参考截图（图片/HTML 原型/Figma 导出），且要求实现页面、组件、弹窗、抽屉、报表、大屏等 UI——无论前后端。目标：交付物与原型在信息结构上**可逐项对照**，禁止"参考着写"、禁止"自由发挥"。

## 硬性阻断（任一命中先处理，不得继续写代码）

1. 原型图未逐张**实际查看**（视觉读取图片内容）：禁止只凭文件名、需求文字描述或会话记忆还原。
2. 当前环境无法查看图片内容（工具不支持读图）→ 阻断并明确告知用户，请求可读格式（HTML 原型源码 / 文字化界面描述），禁止脑补实现。
3. 多张原型相互不一致、或原型与 PRD/口头需求矛盾 → 列出矛盾点，问用户以哪版为准，不自行取舍。
4. 原型关键信息看不清（字段名、按钮文案、表格列、状态图例）→ 逐条列出让用户确认，禁止猜。

## 还原清单（实现前必建，作为验收基线）

逐页面/逐弹窗建立清单，一页一张表：

| # | 区块/控件 | 原型事实（组件类型/布局） | 字段/列与文案（原文） | 交互与状态 | 实现位置 | 还原状态 |
|---|---|---|---|---|---|---|
| 1 | 顶部筛选区 | 下拉×2 + 日期范围 + 查询/重置按钮 | 院区 / 状态 / 起止日期 | 查询触发表格刷新，重置回默认 | `xxx.vue` | ✅ / ❌+理由 |

清单规则：

- 区块从上到下、控件从左到右**逐个登记**；禁止"大致有个表格"级别的粗粒度登记。
- 表格列、表单字段、按钮/标签文案逐一登记**原文**（"启用/停用"不能写成"状态"）。
- **原型中出现的元素清单里必须有；清单中没有的元素不允许出现在实现里**。
- 多状态原型（折叠/展开、弹窗打开、空态、多 tab）每个状态单独登记。

## 实现约束

1. **以原型为准**：布局结构（分栏/上下/主从）、组件类型（表格/树/卡片/抽屉/弹窗）、字段与列集合、按钮及文案、交互行为（点击/刷新/跳转/禁用）必须与原型一致。
2. **禁止增删改**：不擅自新增原型没有的区块/列/按钮/筛选项；不遗漏原型有的元素；不做结构替换（弹窗→页面、表格→卡片、抽屉→下拉）。
3. **允许的标准化偏差**（须在差异报告中注明）：间距/字号/颜色按组件库设计体系标准化；原型示例数据由真实接口数据替代；空态/加载态按组件库惯例补充。
4. **冲突问询**：原型与组件库能力、后端接口能力、既有页面风格冲突时，列出冲突点与两个方案问用户，不自行取舍、不静默降级。
5. **示例数据不入产线代码**：原型的演示数据仅用于理解结构，禁止硬编码进业务代码。

## 验收对照（完成实现后必做）

1. 逐行核对还原清单：每行 ✅，或 ❌+理由（组件库无对应能力 / 用户已确认替换）。
2. 能运行时：实际渲染结果与原型**并排对照**一遍再交付；不能运行时如实标注"未做渲染对照"。
3. 差异汇总进交付总结：未还原项、替换项及理由逐条列出——禁止用"已按原型实现"一句话带过。
4. 需求中途原型更新 → 以最新版为准，同步更新清单，并逐项检查已实现部分是否需要回改（同"需求收窄要回改"原则）。

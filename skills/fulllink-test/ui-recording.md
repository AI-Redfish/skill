# UI E2E 录屏与人工核对

> 使用 Playwright 或其他工具执行端到端 UI 自动化时必读；Python（uv）与 Node.js 均遵守。

## 录制范围与保存

- 每个 UI 场景都录制完整业务操作过程，成功、断言失败、异常都保留视频。
  从第一步业务操作前开始，到最终结果展示后结束；弹窗/新标签页等也要有对应录像。
  截图和 trace 可补充取证，不能代替视频。
- 保存到 `runs/<主题>/videos/<环境>/<场景>/<尝试序号>/`，不放 tmp/、业务仓库或
  skill 目录；目录按场景和重试隔离，保留每次尝试，避免只留最后一次成功录像。
- 场景结束在 finally 中关闭录制 context，确保视频写完，再取得真实路径；核实文件
  存在、大小非零。强杀进程可能损坏视频，不能宣称完成录屏。录制失败/文件缺失
  在报告记“录屏证据缺失”，自动断言结论另行保留，UI 人工核对不能视为完成。
- 自动化工具无内置视频能力时，使用能覆盖实际浏览器窗口的录制工具，通过 Python/Node
  编排并验证录制结果；录制能力不可用则该 UI 场景的录屏要求受阻，说明缺口。
- 优先在已登录的测试会话中开始业务录屏。必须录制登录时使用测试账号和密码遮挡；
  避免展示凭据、令牌、无关敏感数据，必要时提供脱敏副本并标明处理。
  视频默认本地保存并 gitignore，不自动上传或随报告外发。

## 适合人工查看的操作节奏

默认设置在 env.json 的 `uiAutomation` 中，计划和报告记录实际使用值：

- `slowMoMs: 500`：Playwright `launch(slow_mo=500)` / Node `launch({slowMo: 500})`。
- `stepPauseMs: 1000`：每个有意义的 UI 操作完成、预期页面状态已出现后再停留约 1 秒。
  提交、跳转、弹窗和最终结果至少保留这段可观察时间，可按页面复杂度调长。
- `typingDelayMs: 80`：需要让人看清输入过程时，逐字符输入，字符间隔约 80ms。
- `videoSize: {width: 1280, height: 720}`：viewport 和录屏尺寸一致，保证字段及提示可读。

slowMo 不能代替结果展示后的停留。显式等待页面/元素/接口结果是正确性条件，
可读性停留在条件满足后执行，不能用固定 sleep 代替状态等待；不使用长时间阻塞暂停。
无界面运行仍要录屏并保持上述节奏，不因 CI/headless 取消录制或自动改成极速模式。

## Playwright 实现要点

Python 使用 `browser.new_context(record_video_dir=..., record_video_size=...)`；
Node 使用 `browser.newContext({recordVideo: {dir: ..., size: ...}})`。
为所有参与业务操作的页面创建带录制的 context。用 page.video 对应各页，
在 context 关闭完成后取路径；必须先关 context 再关 browser，以完成视频保存。
模板示例见 templates/assets/probes/README.md。

逐步记录操作名称、相对场景开始的秒数、对应页面与预期结果到场景 steps.json，
保存在同一视频目录。报告引用视频文件和关键时间点，便于人工快进核对；多页录像
按页面分别记录时间基准，不把主页面时间点直接当作弹窗录像时间点。
重试记录独立索引，不覆盖已有 steps.json。

## 报告与人工核对

- plan.md 列 UI 场景、录制范围、实际节奏参数和预期人工核对内容。
- report.md 的“UI 录像与人工核对”列出场景、环境、尝试、视频相对链接、关键步骤/
  时间点、自动断言结果、人工核对状态（待核对/已核对/有问题/证据缺失）。
  HTML 由 Markdown 转换，保留同一视频链接；移交时视频目录需与报告一起保存。
- 人工核对关注操作顺序、输入内容、交互状态、跳转/提示及最终页面结果。
  待核对项同步进入人工验证清单，自动断言 PASS 不能写成“人工已核对”。
  自动断言全部通过但视频未人工核对时，总结为“自动断言通过，UI 录像待人工核对”，
  不声称全部验证完成；收到实际核对反馈后再更新 Markdown 和 HTML。

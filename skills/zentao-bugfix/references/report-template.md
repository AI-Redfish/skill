# zentao-bugfix 报告模板

报告生成方式：`scripts/bugfix.py` 的 `prepare` / `report` 子命令会**自动生成两份报告的骨架**（bug 元数据、问题描述、分支信息、变更清单等机械字段已填好），AI 只需用 Edit 补全其中（待填写）的分析性章节。本模板描述补全后的最终形态，均用中文书写。

目录：`<worktree>/.agents/bugfix/<bugId>/`，包含：

1. `analysis.md` —— 问题分析报告（prepare 时生成骨架）
2. `fix-report.md` —— 修复报告（report 时生成骨架，自动含未提交变更清单）
3. `bug.md` / `bug-raw.json` / 截图 —— 禅道 bug 快照（脚本自动拷贝）

---

## analysis.md 结构

```markdown
# BUG #<bugId> 问题分析报告

- **Bug 标题** / **分析日期** / **分析基线（分支 @ hash）** / **远端同步状态（已同步 origin/<基准> / 未同步原因）** / **禅道链接**   ← 脚本自动填

## 1. 问题描述                                       ← 脚本自动填（状态/严重度/重现步骤/评论要点/截图清单）
## 2. 关键信息提取
   业务场景 / 涉及接口或页面 / 日志报错 / 环境          ← 待填写
## 3. 代码定位过程
   用了哪些关键字检索、命中哪些文件、如何缩小范围        ← 待填写
## 4. 根因分析
   ### 原因 1（确认）: 证据（文件:行号）+ 解释
   ### 原因 2（排除/存疑）: ...                        ← 待填写
   **结论**: 一句话根因
## 5. 修复方案设计
   方案对比与取舍 / 选定方案 / 影响面评估               ← 待填写
## 6. 遗留问题 / 待确认
   无法在代码层面确认、需测试或现场配合确认的事项        ← 待填写
```

## fix-report.md 结构

```markdown
# BUG #<bugId> 修复报告

- **Bug 标题** / **修复分支（基于基准分支，含远端同步状态）** / **修复日期** / **修复状态** ← 脚本自动填
- **变更状态**: 未提交——改动保留在 worktree 工作区，等待人工 review 后由人工提交 ← 脚本自动填

## 1. 修复内容                                        ← 待填写（修复思路，对应 analysis 的根因与方案）
## 2. 代码变更清单                                    ← 脚本自动填（文件表格 + 增删统计）
   AI 需在表格每行补充"做了什么改动、为什么"的说明
## 3. 修复验证
   编译命令与结果 / 静态走查结论 / 未覆盖项            ← 待填写
   （Maven 项目在 worktree 下编译需加 -Dmaven.gitcommitid.skip=true）
## 4. 测试建议（给 QA）
   环境、步骤、预期                                   ← 待填写
## 5. 风险与回滚
   风险等级与理由；未提交状态回滚 = git checkout -- <文件> / 删除未跟踪文件 ← 待填写
## 6. 产物位置                                        ← 脚本自动填
```

**注意**：报告中**不出现提交 hash**（流程约定不自动 commit，变更以工作区 diff 为准）；引用代码位置用 `文件路径:行号`；敏感信息（生产地址、账号密码）一律脱敏。
